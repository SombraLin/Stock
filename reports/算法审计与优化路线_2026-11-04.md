# 买卖点算法审计与优化路线

日期：2026-11-04，Asia/Shanghai。结论：当前证据不足以把任何一套规则认定为可盈利交易策略。优先修复信息可用时间、推荐记录和评估口径，再研究参数与因子。

## 1. 第一性原理：买卖点必须创造什么价值

买点的价值来自：在当时可获得的信息下，未来**可成交**卖价的条件期望，超过买入总成本、卖出费用与风险补偿。卖点则必须证明相对继续持有或稍后接回有收益改善。指标名字、共振数量、历史胜率都不能替代这一判断。

`预期净收益 = 条件价格变化 − 佣金 − 印花税/过户费 − 买卖价差/滑点 − 冲击成本`。

两种账户约束分别处理：

- **新开仓 T+1**：当天新买的普通股票不能当天卖出；盘中止损触发也不意味着可以执行。需要隔夜敞口和跳空风险评估。
- **底仓做 T**：卖出必须有足够可卖底仓；买入后卖出旧底仓，或先卖旧底仓再接回，分别衡量相对原持仓的增量收益。现金、可卖股数和仓位必须守恒。

交易规则依据：[上交所交易规则（2026年修订）3.1.4](https://www.sse.com.cn/lawandrules/sselawsrules2025/trade/universal/c/c_20260424_10816492.shtml)、[深交所交易规则（2026年修订）](https://docs.static.szse.cn/www/lawrules/rule/trade/current/W020260424690713155663.pdf)。印花税参考：[上交所股票投资费用说明](https://one.sse.com.cn/onething/gptz/)、[减半征收公告](https://shanghai.chinatax.gov.cn/tax/zcfw/zcfgk/yhs/202308/t468451.html)。实际佣金应以用户券商账单为准。

## 3. 当前算法实际做了什么

|策略|买入条件概要|主要问题|
|---|---|---|
|布林回归，默认推送策略|前一根低点触下轨、当前收盘回下轨上方、RSI<40|猜测短期均值回归；未区分趋势下跌与暂时偏离|
|锤子线|下影比例>58%、实体<28%、RSI<42、靠近下轨|形态比例未约束绝对振幅；极小K线也可能满足|
|放量突破|收盘穿越MA20、成交量>20根均量1.5倍|日内成交量具有时段季节性，开收盘与午盘不可直接混比|
|午后/全天多因子|BOLL、RSI、MACD、均线突破、相对强弱人工加分，阈值4|多项因子来自同一价格序列，不等于多条独立证据|
|RSI极值、MA交叉、MACD交叉|阈值反弹/均线或动量交叉|作为对照合理，缺乏独立净收益证明|

所有策略从第60根开始；同方向连续信号间隔至少6根，但若中间出现反向信号可更快重复。止损/止盈主要为固定百分比；虽然计算了ATR，实际交易计划并未用ATR自适应定价。卖点是对称的看空规则，旧评估函数只统计买点，未验证卖点收益。

## 4. 足以改变结论的问题

1. **未收盘K线参与推荐。** 线上22条通知中18条 `created_at < signal_time`。例如11月4日10:55 K线的信号于10:50:08推送。结合每分钟抓取、未过滤收盘时间的代码，这是使用形成中K线的重要证据；该问题会造成信号重绘。仍需确认服务器与数据源时钟同步，不能仅凭时间字段认定全部差异来源。
2. **交易约束缺失。** `evaluate_signals` 和旧配对引擎允许新开仓后日内卖出；模拟账户也没有可卖数量/T+1台账。旧止损回测使用阈值价成交，未处理跳空、停牌、涨跌停封单和市场深度。
3. **成本缺失。** 历史收益没有扣佣金、最低5元门槛、印花税、过户费与滑点。很多信号的毛收益仅几个基点。
4. **介绍、研究与线上条件不一致。** 旧锤子线是下影>60%、实体<25%、RSI<40，当前为58%/28%/42；旧RSI阈值25/75，当前26/74；旧多因子门槛3.5、相对强弱权重1，当前4和0.5。旧研究不按线上6根规则去重。直接复用旧胜率和“旗舰/黄金窗口”称谓不成立。
5. **旧数学期望公式对零收益处理错误。** `calc_metrics` 把零收益样本算入失败概率，又乘非零亏损均值。因此旧布林平均毛收益0.091%与所谓期望0.082%不一致。正确的经验期望就是包含零值的逐笔收益均值。
6. **重叠信号不能直接复利。** 旧研究把可能同时占用资金的多个事件收益连乘，得出的累计收益、回撤不能代表可交易账户。60分钟实际上是12根交易K线，午休、收盘和隔夜会延长墙上时间。
7. **固定历史窗口存在选择偏差。** 在同一股票、同一数据上挑最优策略与最佳时段后，再展示其胜率，会高估泛化效果。199天招行结论不能直接搬到平安银行。
8. **当前决策卡片没有完整退出状态。** 历史BUY仍可持续显示为持股建议，却未确认实际成交、可卖数量、是否已经止盈止损。SELL也未区分有仓减持与无仓观望。

## 5. 重算结果

统一假设：每次1,000股；佣金万2.5、最低5元/笔；卖出印花税0.05%；过户费双边各0.001%；滑点双边各5bp。使用当前代码生成推荐点，信号后下一根K线开盘作为假设入场，12根后开盘作为假设离场。均为**事件研究**，允许重叠，只报告单事件均值，不构造账户收益率。开盘价不是已验证成交价，费用也不是用户真实账单。

|当前策略|招行12根后平均净收益|平安12根后平均净收益|
|---|---:|---:|
|布林回归|−0.160%|−0.238%|
|锤子线|−0.216%|−0.303%|
|放量突破|−0.128%|−0.159%|
|午后共振|−0.155%|−0.235%|
|全天共振|−0.157%|−0.215%|
|RSI反转|−0.225%|−0.261%|
|MA交叉|−0.189%|−0.213%|
|MACD交叉|−0.187%|−0.227%|

布林回归的固定12根评估样本为招行235个、平安272个；样本需要完整后续数据，并剔除跨越时间切分边界的标签。招行平均净收益95%按日聚类区间约[−0.233%, −0.089%]，平安约[−0.305%, −0.171%]。这未证明任何市场永久无效，但足以否定现有数据对“稳定盈利”的支持。

**按用户要求分开的评估**，以下来自全部历史布林台账，不做时间切分边界剔除，样本口径与前表略有区别：

|模式|招行 样本/平均净收益|平安 样本/平均净收益|
|---|---:|---:|
|新开仓，至少等到买入下一有行情日期，且满足12根目标后再卖|235 / −0.176%|272 / −0.353%|
|底仓做T：买点后买入、12根后卖出等量旧底仓，信号/进出场均同日|176 / −0.190%|194 / −0.231%|
|底仓做T：卖点后卖出旧底仓、12根后接回，信号/进出场均同日|188 / −0.203%|172 / −0.269%|

卖点收益衡量的是扣费后的“先卖后接回”价差，不能解读成裸卖空收益或直接证明减仓防守无效。没有真实成交/持仓流水时，所有模式都标记为假设、底仓未验证。

**成本敏感性。** 招行布林即便滑点为0，1,000股均值仍约−0.060%；平安约−0.138%。不是仅靠降低5bp滑点就能解决。平安每笔金额较小，最低佣金影响更大。100股并不会自动更稳健，反而会显著增加费率；也不能据此建议增仓来摊薄费用。

**尾盘高胜率不能直接转化为盈利。** 招行尾盘布林的27个完整样本，原信号收盘到12根后收盘毛胜率仍为66.7%；换成下一根开盘、扣费后，均值仅+0.014%，净胜率51.9%，均值95%聚类区间[−0.250%, +0.282%]，覆盖0。多数尾盘60分钟窗口跨日，不是同日日内做T。

**时间稳定性。** 以有行情日期按60%/20%/20%顺序切分，边界为7月7日、9月1日，并剔除跨边界标签。9月1日起的末段，布林招行47个样本平均净收益−0.299%，平安56个−0.280%。由于原系统已看过这段历史，不能称作真正未触碰样本外验证；下一段实时冻结记录才是前瞻验证。

无条件入场对照的12根净收益约为招行−0.199%、平安−0.239%；布林可能比粗糙对照少亏，但这既不是正收益，也没有证明独立alpha。下一轮必须增加同股票、同时间段、同市场状态的匹配对照。

## 6. 优化假设登记与验收

以下都是**待验证假设**，本次不通过修改RSI/BOLL阈值来追求历史最好结果。

|编号/优先级|假设或修复|实验方法|验收依据/当前状态|
|---|---|---|---|
|R01 / P0|形成中K线制造虚假信号|仅收盘后5秒纳入；记录首次出现时间、当时完整输入与版本|本地已实现；新实时推荐不得早于K线结束；待生产应用|
|R02 / P0|无成本/T+1口径高估收益|两种持仓模式分账；资金、可卖股数、最低佣金与跳空成交状态机|本地事件标签已实现；完整账户撮合与T+1模拟账户约束待做|

|R04 / P1|均值回归仅在震荡环境有效|用推荐时已知的历史波动、均线斜率和市场趋势分层；趋势过滤做单因素消融|按净收益、相对匹配对照、覆盖率评估；待实验|

|R06 / P1|固定止盈止损不适应波动|用当时ATR/价格比、最小价位和成本底线设风险预算；约束隔夜可执行性|净收益/回撤/换手共同改善；待账户引擎后实验|
|R07 / P1|相关因子重复计票|逐个删除BOLL/RSI/MACD/MA因子；简化模型与原模型并行|保留跨月份、跨股票稳定的增量；待实验|
|R08 / P1|事件去重仍造成过度交易|按持仓周期、可卖底仓与冷却状态形成一次交易决策|比较含成本账户收益、交易次数和错失机会；待实验|

推荐优化顺序：R01/R02/R03先落地，再按R04/R05/R08逐项实验，最后考虑增加模型复杂度。提升预测胜率但增加成本或降低盈亏比，不算优化成功。

## 7. 推荐点记录与持续反馈，已完成的本地实现

`backend/recommendations.py` 使用独立的 `data/recommendations.db`，不与模拟账户混用。

- 已归档976个历史布林买卖点：招行477个、平安499个；生成4,404条不同模式/期限的成熟评估。**全部为 historical_replay，没有伪装成实时推荐。**
- 推荐身份包含股票、策略、算法版本、K线时间、方向、来源；首次记录后不覆盖。版本表保存策略源码与费用策略；快照保存理由、交易计划、当时指标、输入指纹、最近80根股票和基准K线，实时记录另存完整计算输入。
- 实时推荐仅纳入最近3根已收盘K线，且距观察时间不超过20分钟；不把历史网页查询当成实时推荐。记录不依赖通知开关、通知成功与否。
- 评估与推荐分表，未来收益不写进推荐快照。未成熟期限保持待评估，结果生成后只插入一次。实时成交代理使用**首次观察之后**的第一个可用K线开盘，避免拿已过去的开盘价成交；与上面的理想化下一根开盘历史审计口径有区别。
- 标签涵盖6/12/24/48根交易K线的底仓价差，以及买点12根目标与T+1约束共同决定的离场。卖点为旧底仓卖出后接回，绝不默认允许卖空。
- 汇总按股票/版本/实时或回放/买卖方向/模式/期限分组，底仓模式汇总只含同日事件；提供样本数、均值、中位数、胜率、按日聚类区间。原始记录保留跨日事件及时间戳。
- 同步任务已接入实时记录和后续评估；API `/api/recommendations` 查询台账，`/api/recommendations/summary` 查询分组评估。网页策略分析与推送扫描均加入收盘过滤。

**边界：尚未部署服务器。** 现有线上前端仍显示旧描述，原模拟账户仍缺少T+1可卖股数。未修改指标阈值、执行真实交易或发送测试通知。本地测试通过不代表收益通过验收。

## 8. 后续迭代纪律

每日同步后自动成熟标签；每周先检查数据缺失、提前推荐、重复推荐、推荐到成交代理的延迟与模式混用，再查看净收益。每月固定一次候选策略评审；样本少则延长观察，不强行更新。

每次实验登记：假设编号、代码版本、训练/验证/前瞻区间、股票范围、费用和仓位假设、唯一主要指标、尝试过的参数集合。逐项变更，保留旧版作为同时运行的对照，避免只挑最好结果。

晋级建议：至少跨越60个新交易日、积累100个成熟且按独立持仓周期整理的事件，两只股票分别报告；成本压力测试、匹配对照差额、区间估计和账户回撤均需检查。该样本门槛只是治理起点，不是统计有效性的保证。若净收益置信区间仍覆盖0或效果集中在少数日期，继续观察。自动化只负责记账和评估，不自动把历史最优参数替换到线上。

账户引擎还应补充：逐笔成交/委托、现金与持仓lot、可卖数量、真实滑点、执行失败、资金占用、最大回撤、相对持有基准收益、公司行为和完整交易日历。没有这些，不能把当前事件统计称为完整可交易回测。

## 9. 复现命令

```bash
python3 -m backend.research_audit --output reports/audit_2026-11-04.json
python3 -m backend.recommendations --replay --evaluate
python3 -m backend.recommendations --summary
python3 -m unittest discover -s tests -v
```

`--replay` 明确标记为历史回放、支持幂等运行；不会发消息。运行中的服务器启用新代码后才会产生 `live` 记录。研究结果文件和推荐台账应备份；台账运行文件已加入gitignore，避免把持续变化的数据库纳入代码版本。
